# Feature request: Discord attachment delivery

## Goal

Let the agent send image/audio/file payloads generated by provider APIs or other tools through the Discord bridge, not just plain text. This makes it possible to surface binaries such as Gemini-generated images without asking the user to fetch them manually.

## Problem

The current Discord dispatcher only forwards `payload.content`, so tool responses that are base64 blobs or file URLs never reach Discord as attachments. As soon as a tool produces media, the bridge needs to know how to treat it—convert base64 to `Buffer`, download referenced URLs, attach a filename, and hand the result to `channel.send` as `files`. Without that, media-generating tools are unusable in Discord.

## Proposed solution

1. Extend the dispatcher interface to accept a richer payload: `{
   content?: string,
   files?: Array<{ attachment: Buffer | string | URL, name: string }>,
   embeds?: any[]
}`.  
2. Have tools that emit media set metadata fields such as `contentType`, `filename`, `description`, and an estimated `size`.  
3. Add a centralized attachment helper that respects Discord limits (10 files / message plus per-account size caps) and logs or rejects payloads that would exceed them.  
4. Keep short-circuit fallbacks: if the dispatcher can’t send the attachment (too large, wrong MIME type), include a textual fallback that describes what failed and optionally links to a hosted version.

## Constraints

- Standard Discord accounts cap individual attachments at 8 MB. Nitro Classic raises that to 50 MB and full Nitro to 100 MB. The dispatcher should compare the helper’s size estimate before attempting uploads and decline gracefully if a payload would exceed the available limit.  
- Discord allows up to 10 attachments per message. Track the count and refuse or fall back once the limit is hit.  
- Attachments should ideally be non-streaming (`Buffer` or temporary file) so the Discord client can pass them along reliably.  
- Each attachment must have a filename and accurate `contentType` so Discord can label it correctly and mime-match the upload.

## Acceptance criteria

- `sendDiscordMessage()` (or equivalent) can accept `files` and relay them via `channel.send`.  
- Provider tools that flag their result as binary can trigger the attachment path without manual intervention.  
- The dispatcher enforces Discord’s limits and surfaces clear failure messages when attachments can’t be delivered.
